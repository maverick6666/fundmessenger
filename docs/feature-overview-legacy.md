## 0. 전체 구조 — 3대 기능과 상호작용

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│   펀드팀     │     │   동아리     │     │  커뮤니티    │
│  (Fund)     │     │  (Club)     │     │ (Community) │
│             │     │             │     │             │
│ 매매관리     │     │ 조직운영     │     │ 공개 광장    │
│ 포지션추적   │     │ 게시판/일정  │     │ 종토방      │
│ 토론/의결    │     │ 스터디      │     │ 마켓플레이스  │
│ 운용보고서   │     │ 팀관리      │     │ 리더보드     │
└──────┬──────┘     └──────┬──────┘     └──────┬──────┘
       │                   │                   │
       │    ┌──────────────┴───────────────┐   │
       │    │      콘텐츠 내보내기           │   │
       │    │  (동아리 → 커뮤니티 채널)      │   │
       └────┤                              ├───┘
            │  • 운용보고서 내보내기 (공개/유료)│
            │  • 팀장 글 내보내기            │
            │  • 칼럼 내보내기              │
            │  • 크레딧 수익/지출           │
            └──────────────────────────────┘
```

### 상호작용 요약

| From → To | 무엇이 이동하는가 | 누가 할 수 있는가 |
|-----------|-----------------|-----------------|
| 펀드팀 → 커뮤니티 | 운용보고서 내보내기 | 팀장 (공개 or 유료 잠금) |
| 동아리(팀장 글) → 커뮤니티 | 팀 게시글 내보내기 | 회장/부회장 + 해당 팀장 |
| 동아리(칼럼) → 커뮤니티 | 개인 칼럼 내보내기 | 작성자 본인 |
| 커뮤니티 → 크레딧 | 콘텐츠 구매 시 크레딧 이동 | 구매자 동아리 → 판매자 동아리 |
| 커뮤니티 → 동아리 | 내보낸 콘텐츠 관리 (공개↔비공개, 가격 변경) | 회장/부회장/팀장/작성자 |

### 1.2 동아리 라이프사이클 — 계약부터 기수 전환까지

> 동아리 기능은 "사용자가 앱을 여는 순간"이 아니라 **"오프라인 계약"**에서 시작한다.

---

#### Phase 0: 계약 → 동아리 개설 ✅ 구체화 완료

**전제**: PG사 연동 없음 (의도적). 계약은 오프라인 계좌이체 (반년/연간).

```
[오프라인] 우리 회사 ←→ 동아리 회장단: 계약 체결, 계좌이체
  ↓
[SUPER_ADMIN 관리페이지]
  → 학교명/동아리명 등록 → Organization 레코드 생성
  → 구독 활성화 (기간 설정, 번들 크레딧 지급)
  ↓
동아리가 플랫폼에 "존재"하게 됨 (아직 아무도 없는 상태)
```

**SUPER_ADMIN이 하는 일:**
- 학교/동아리 등록
- 구독 상태 ACTIVE로 변경
- 구독 기간 설정 (startDate, endDate)
- 번들 크레딧 지급

**프론트엔드**: SUPER_ADMIN 전용 관리페이지 — ❌ **페이지 없음** (admin/ 스켈레톤만)

---

#### Phase 1: 회장 가입 → 초기 세팅 ✅ 구체화 완료

```
회장이 회원가입
  → 학교/동아리 선택 (이미 등록된 목록에서)
  → 이메일 인증
  → "승인 대기" 상태
  ↓
[SUPER_ADMIN 관리페이지] → 최초 회장 승인
  ↓
회장 로그인 가능
  ↓
[동아리 관리페이지 — ClubAdminPage]
  → 상단: 기수 설정 (예: "33기")
    ※ 기수 = 단순 텍스트가 아닌 "세션" 개념
    ※ 이후 가입자는 자동으로 "33기 OOO"로 기록
    ※ 설정 가능 (실제 기수와 다를 수 있음)
```

**핵심 규칙:**
- 최초 회장만 SUPER_ADMIN이 승인
- 이후 모든 부원은 회장/부회장이 승인
- 회장도 처음엔 "일반 가입" → SUPER_ADMIN이 회장 역할 부여

#### Phase 2: 부원 가입 → 역할 배정 → 팀 구성 ✅ 구체화 완료

```
부원이 회원가입
  → 학교/동아리 선택
  → 이메일 인증
  → "승인 대기" 상태 (로그인 불가)
  ↓
[동아리 관리페이지 — ClubAdminPage]
  회장이 가입 요청 목록에서 승인
  ↓
부원 로그인 가능 (역할: 일반 부원, 팀 미소속)
  ↓
회장이 관리페이지에서 역할 배정:
  → 부회장 지정 (1~2명)
  → 나머지는 일반 부원으로 유지
  ↓
회장/부회장이 팀 생성:
  → 팀 이름 설정 (예: "김강산팀")
  → 팀 유형 선택 (FUND/ANALYSIS/REAL_ESTATE/CUSTOM)
  → 팀장 지정
  ↓
★ 팀이 생성되면 → 동아리 메인페이지 게시판에 "32기 김강산팀" 탭이 자동 추가
  ↓
팀장이 팀원 배정 (또는 회장/부회장이 배정)
  → 미소속 부원 목록에서 드래그 or 선택
```

**역할 부여 순서:**
1. 회원가입 → 모두 "승인 대기"
2. 회장 승인 → "일반 부원" (미소속)
3. 회장이 부회장 지정
4. 회장/부회장이 팀 생성 + 팀장 지정
5. 팀장 or 회장/부회장이 팀원 배정

##### 관리페이지 멤버 관리 UI (ClubAdminPage)

```
┌─────────────────────────────────────────────┐
│  [필터: 전체 | 미배정 | 팀별 | 역할별]       │
│                                             │
│  👑 이학현 (회장)                             │
│  ⭐ 김서연 (부회장)                           │
│  ⭐ 박준영 (부회장)                           │
│                                             │
│  ── 김강산팀 ──────────────────── [팀 설정]  │
│  🔷 김강산 (팀장)                             │
│  · 이수민 (팀원)                              │
│  · 정다은 (팀원)                              │
│                                             │
│  ── 박서준팀 ──────────────────── [팀 설정]  │
│  🔷 박서준 (팀장)                             │
│  · 김강산 (팀원) ← 다른 팀의 팀장이면서 여기선 팀원│
│                                             │
│  ── 미소속 ────────────────────────────────  │
│  · 최유진                                    │
│  · 한지우                                    │
│                                             │
│  [+ 팀 추가]                                 │
└─────────────────────────────────────────────┘

조작 방식:
  • 부원 드래그 → 팀 영역에 드롭 = 팀원 배정
  • 부원 이름 클릭 → 역할 변경 (부회장/팀장 지정)
  • [+ 팀 추가] → 팀 이름 입력 + 팀장 선택 → 팀 생성 (하위에 빈 공간)
```

##### 멀티역할/멀티팀 규칙

> 동아리마다 운영 구조가 다르므로 유연하게 지원

| 케이스 | 허용 여부 |
|--------|---------|
| 1인 1팀 소속 | ✅ (기본) |
| 1인 다수 팀 소속 (팀원으로) | ✅ |

| 팀장이 2~3개 팀의 팀장 | ✅ |

- 관리페이지 필터로 복잡한 관계를 쉽게 파악:
  - **미배정**: 아무 팀에도 안 속한 부원
  - **팀별**: 특정 팀 소속만 보기
  - **역할별**: 팀장만 / 부회장만 / 졸업자만

**프론트엔드 필요:**
- `ClubAdminPage.tsx` — 가입 승인 + 역할 배정 + 팀 생성/관리 (✅ 존재, 드래그&드롭 미구현)
- 회원가입 시 학교/동아리 선택 UI (✅ 존재)

#### Phase 3: 기수 전환 (계승) ✅ 구체화 완료

> 핵심: 기수 전환 = "새 시즌 시작". 이전 기수 데이터는 보존되되, 팀 해체 + 새 회장 선출.

```
현재: 33기 운영 중
  ↓
회장이 관리페이지에서 "34기 생성" 클릭
  ↓
34기 페이지 생성됨:
  • 33기의 전체 명단이 34기로 복사 (기본값)
  • 단, 모든 팀은 해체됨 (팀장/팀원 관계 초기화)
  • 33기 데이터(게시판, 팀 기록 등)는 아카이브로 보존
  ↓
회장이 "차기 회장" 선택 (기존 인원 중)
  → 차기 회장 승인 시 → 회장 권한 이전
  ↓
새 34기 회장이 동일 워크플로우 반복:
  → 부회장 지정
  → 팀 생성 + 팀장 지정
  → 팀원 배정
```

**기수 전환 시 일어나는 일:**
| 항목 | 동작 |
|------|------|
| 멤버 명단 | 전체 복사 (탈퇴자 제외 가능) |
| 팀 | 전부 해체 (팀원 소속 관계 초기화, 팀 자체는 아카이브 보존) |
| 회장/부회장 | 초기화 (새 회장 선택 필요) |
| 게시판 글 | 33기 아카이브로 이동 (열람 가능, 수정 불가) |
| 포지션/요청 | 33기 아카이브 (새 기수에서 새로 시작) |
| 크레딧 잔액 | 동아리 단위이므로 유지 |
| 구독 | 유지 (기수와 무관) |
| **드라이브 PDF** | **삭제 안 됨** — 기수 태그 유지, 팀 태그 유지. 기수 필터로 열람 가능 |

**확정 사항:**
- [x] 이전 기수 아카이브 → **읽기 전용으로 열람 가능**
- [x] 졸업자 → **"졸업" 태그** 부여 (계정 삭제 아님)
- [x] 졸업자 접근 → **동아리 열람 가능 + 자유게시판/칼럼에 글 작성 가능 + 종토방 참여 가능 + 플로팅 패널 접근(채팅/DM/공지/캘린더, 팀 채팅만 자연 제외)**
- [x] 졸업자 권한 세밀 제어 → **회장/부회장이 동아리 설정에서 채널별 허용/차단 토글** (ClubAdminPage 설정 탭)

**기수 전환 시 승계되는 설정:**
- 게시판 구조 (커스텀 게시판, 세미카테고리 등)
- 동아리 기본 설정들

#### 플로우 B: 동아리 게시판 구조 ✅ 구체화 완료

> 게시판은 단순 목록이 아니라 **회장이 커스터마이징하는 구조**

##### 핵심 개념: 게시판 = "누가 쓸 수 있는가", 세미카테고리 = "어떤 종류의 글인가"

```
게시판 (Board) → 글쓰기 권한 단위
  "이 게시판에 누가 글을 쓸 수 있느냐"

세미카테고리 (SemiCategory) → 글 분류 단위 (동아리 전체 공통)
  "이 글이 어떤 종류의 글이냐" — 글 작성 시 선택
  모든 팀 게시판에 동일하게 적용 (전체 필터에서 의미 있으려면 공통이어야 함)
```

##### 게시판 구조

```
동아리 게시판 (ClubBoardPage)
│
├── [필터] 전체 — 모든 게시판의 글을 한번에 봄
├── [필터] 팀별 — 특정 팀의 글만 봄
│
├── [자동 생성] 팀 게시판 — 팀 생성 시 자동 추가
│   ├── "33기 김강산팀" → 김강산팀 팀원+팀장만 글쓰기
│   ├── "33기 박서준팀" → 박서준팀 팀원+팀장만 글쓰기
│   └── ... (팀 수만큼)
│
└── [커스텀] 회장이 생성한 게시판 — 권한 설정 가능
    ├── 예: "졸업자 게시판" → 권한: 졸업자만
    ├── 예: "자유게시판" → 권한: 전체 (팀 상관없이 누구나)
    ├── 예: "칼럼" → 권한: 전체
    ├── 예: "공지사항" → 권한: 회장/부회장만
    └── ... (회장이 자유롭게 구성)
```

##### 커스텀 게시판 권한 설정 (회장이 게시판 생성 시 선택)

| 권한 옵션 | 글쓰기 가능 대상 | 예시 게시판 |
|-----------|----------------|-----------|
| **팀 전용** (기본) | 해당 팀원 + 팀장 | 팀 게시판 (자동 생성) |
| **전체** | 모든 부원 + 미소속 + 졸업자 | 자유게시판, 칼럼 |
| **졸업자만** | 졸업 태그 인원 | 졸업자 게시판 |
| **회장단만** | 회장 + 부회장 | 공지사항 |
| **커스텀** | 회장이 직접 체크 | 필요시 |

> 읽기는 동아리 소속이면 누구나 가능 (졸업자 포함). 글쓰기만 권한 제한.

```
├── "2주차 세미"

├── "시장분석"
```

#### 플로우 D: 팀 스터디 ✅ 구체화 완료

> **배경**: 동아리 카페(네이버)가 죽는 이유 = ①올 동기 없음 ②글 작성 슬러지
> **해결**: 스터디 자료를 앱에서 관리 + AI가 자료 기반 글을 대신 작성 → 슬러지 제로

##### 핵심 변경사항 (기존 계획 대비)
- ~~녹음 기능~~ → **제거** (음성→텍스트 수동 변환 비용 과다)
- ~~1스터디 = 1글~~ → **1스터디 = 팀원 수만큼 글** (각자 분석한 기업별)
- 킬러 피처: **PDF → AI 기업분석 글 자동 생성**

##### 스터디 세션 = 컨테이너 (폴더)

> 세션은 "글"이 아니라 **자료들을 묶는 폴더**. 이름은 자유 (꼭 "1차 스터디"일 필요 없음).
> 동아리 전체 게시판에서는 각 글에 붙는 태그 정도의 역할.

```
스터디 세션 (컨테이너)
│
├── 자료 A — 팀원1이 올린 PDF (예: "삼성전자 분석.pdf")
│   ├── [상단] PDF 뷰어 (다운로드 없이 인앱 렌더링)
│   └── [하단] 코멘트 스레드 (실시간 WebSocket)
│       ├── 팀원2: "PER 비교 부분 근거가 약한듯"
│       ├── 팀원3: "p.12 차트 좋다"
│       └── ... (발표 들으면서 실시간으로 코멘트)
│
├── 자료 B — 팀원2이 올린 PDF (예: "카카오 분석.pdf")
│   ├── [상단] PDF 뷰어
│   └── [하단] 코멘트 스레드 (실시간 WebSocket)
│
└── 자료 C — ...
```

##### 코멘트 스레드 — 실시간 (WebSocket)

- 댓글 submit → WebSocket으로 같은 자료를 보고 있는 팀원들에게 즉시 push
- **글자 단위 실시간이 아님** — 댓글 전송 시점에 표시 (채팅방과 동일 원리)
- 기존 토론 채팅(Discussion WebSocket)과 동일 구조 재활용 가능
- 스터디 끝난 뒤에도 코멘트 열람 가능 (아카이브)

##### 페이지별 코멘트 ✅ 구현 완료

- PDF 자료에 **페이지 번호별로** 코멘트를 달 수 있음
- `page_number` 필드 (선택적): null이면 전체 코멘트, 숫자면 해당 페이지 코멘트
- **전체 코멘트 보기 모드**: 해당 자료의 모든 코멘트를 한번에 조회
- **페이지별 보기 모드**: 특정 페이지의 코멘트만 필터링하여 조회
- **코멘트가 있는 페이지 목록** 조회 API 제공 → PDF 뷰어에서 코멘트 있는 페이지 표시에 활용

##### 스터디 플로우

```
[팀 스페이스 페이지]
  ↓
팀장이 "스터디 세션 열기" → 세션 이름 입력 (자유)
  ↓
각 팀원: 자기가 분석한 기업의 PDF 업로드
  → 세션 안에 자료로 추가됨
  ↓
스터디 진행:
  → 발표자의 PDF를 뷰어로 열고
  → 다른 팀원들은 하단 코멘트 스레드에 실시간 코멘트 작성
  → 발표자 교체 시 다른 자료 열기
  ↓
스터디 후: "AI 글 생성" 버튼 (특정 자료 선택)
  → AI에 전달되는 것: PDF 내용 + 해당 자료의 코멘트들
  → 비용: 1크레딧/건 (동아리 공용 크레딧 차감)
  ↓
글 작성 워크플로우 (일반 글쓰기와 동일):
  → 제목 입력
  → 세미카테고리 선택
  → AI 초안 내용 확인/수정
  → 작성자 = PDF 올린 사람 (자동 설정)
  ↓
팀 게시판에 게시됨
  → 작성자가 이후에도 수정 가능
```

##### AI 글 생성 권한 — 동아리 CONFIG로 관리

> 회장/부회장이 관리페이지에서 설정:

| 설정 옵션 | 설명 |
|-----------|------|
| **전체 허용** | 동아리 모든 부원이 AI 생성 가능 |
| **선택 인원만** | 회장이 지정한 인원만 가능 |

- 스터디 세션 안에서든, 일반 글 작성에서든 동일한 권한 적용
- 스터디 세션 없이 개인이 PDF 올려서 AI 글 생성도 가능 (권한 있으면)
- AI 생성 비용은 항상 동아리 공용 크레딧에서 차감

##### "AI 작성" 세미카테고리 — 기본 탑재

- 모든 동아리에 **"AI 작성"** 세미카테고리가 기본으로 존재 (삭제 불가)

- 일반 부원은 이 카테고리로 글을 직접 쓸 수 없음 (AI 전용)

##### AI 자동 주간 리뷰 — 주 1회 자동 생성

```
매주 [요일 설정 가능] 자동 실행 (ScheduledTasks)
  ↓
Cerebras API (gpt-oss-120b)에 전달:
  • 이번 주 동아리 전체 게시글 (팀별)
  • 각 글의 조회수/댓글수/좋아요 (인기도)
  ↓
AI가 생성하는 콘텐츠 (2가지):

1. "이번 주 베스트 글 재조명"
   → 가장 반응이 좋았던 글을 선정
   → AI가 해당 글 내용을 요약/재작성하여 하이라이트

2. "이번 주 동아리 위클리 리뷰"
   → 팀별 활동 요약 (어떤 팀이 몇 개 글, 어떤 주제)
   → 전체적인 동아리 분위기/트렌드 정리
   → 주요 토론 이슈 요약
  ↓
자동으로 팀 게시판이 아닌 **동아리 전체 게시판**에 게시
  → 세미카테고리: "AI 작성"
  → 작성자: "AI 어시스턴트" (시스템 계정)
```

##### 크레딧 비용

- 주간 자동 리뷰: **무료** (구독에 포함)
- 수동 AI 글 생성 (스터디 PDF 등): 1크레딧/건

|------|------|------|--------|

## 5. 미구체화 항목 — 동아리 기능 완전 구체화 목록

> 아래 항목들은 구현에 필요하지만 아직 구체화되지 않은 기능들이다.
> 각 항목은 대화를 통해 구체화한 뒤 해당 플로우 섹션에 삽입한다.

### 🔴 필수 구체화 (기능 완성에 반드시 필요)

#### 5.1 팀 멤버 배정 UI ✅ 구체화 완료

> 위치: **ClubAdminPage → 멤버 탭**
> 핵심: 역할 승격 + 팀 생성 + 드래그 배정이 하나의 화면에서 이루어짐

##### 화면 레이아웃 (위에서 아래로)

```
┌─────────────────────────────────────────────────────┐
│  👑 이학현 (회장)                                     │
│  ⭐ 김서연 (부회장)  ⭐ 박준영 (부회장)                  │
├─────────────────────────────────────────────────────┤
│  [김강산팀] [박서준팀] [이수민팀]  ← 팀장 탭 전환        │
│  ┌─── 김강산팀 ──────────────────────────────────┐  │
│  │ 🔷 김강산 (팀장)           [팀+]              │  │
│  │ · 정다은                                      │  │
│  │ · 한지우                                      │  │
│  │                                               │  │
│  │         ← 드래그 드롭 영역 (빈 공간 펼쳐짐)     │  │
│  └───────────────────────────────────────────────┘  │
├─────────────────────────────────────────────────────┤
│  일반부원  [미소속 ▾] [전체 ▾]  🔍 이름 검색           │
│                                                     │
│  · 최유진  [역할 ▾]                                  │
│  · 이하은  [역할 ▾]                                  │
│  · 김도현  [역할 ▾]                                  │
│  · ...                                              │
└─────────────────────────────────────────────────────┘
```

##### 역할 승격 플로우

1. **초기 상태**: 회장만 상단, 나머지 전부 "일반부원" 섹션에 표시
2. **부회장 지정**: 일반부원 옆 `[역할 ▾]` 드롭다운 → "부회장" 선택 → 상단 회장 아래로 이동
3. **팀장 지정**: 일반부원 옆 `[역할 ▾]` 드롭다운 → "팀장" 선택 → 중간 팀장 섹션으로 이동 + `[팀+]` 버튼 활성화
4. `[역할 ▾]` 드롭다운 옵션: 부회장 / 팀장 / 일반부원 (버튼 늘어놓으면 구리니까 드롭다운 하나로)
5. `[역할 ▾]` 드롭다운은 **모든 인원에게 표시** (팀장→부회장, 부회장→일반부원 등 언제든 역할 변경 가능)

##### 팀 생성 플로우

1. 팀장이 된 인원 옆에 `[팀+]` 버튼 표시
2. `[팀+]` 클릭 → 팀 이름 입력 → 팀 생성
3. 팀 생성 시:
   - 팀장 주변에 **테두리(보더)** 활성화 → 팀 영역 시각화
   - 팀장 탭 바에 새 탭 추가
   - **플로팅 패널에 해당 팀 채팅방 자동 생성** (팀원 전원 자동 참여)
4. **한 팀장이 여러 팀 가능**: `[팀+]`를 다시 누르면 팀2 생성 → 팀1/팀2 탭으로 전환, 테두리 색상도 변경

##### 팀원 배정 플로우 (드래그 + 체크박스 2가지)

**방법 1 — 드래그앤드롭**
1. 하단 일반부원 목록에서 부원을 **드래그**
2. 팀장의 테두리 영역으로 **드롭**
3. 테두리 하단 빈 공간이 펼쳐지며 부원이 팀에 들어감

**방법 2 — 체크박스 일괄 편입**
1. 하단 일반부원 목록에서 여러 부원 **체크박스 선택**
2. "OO팀으로 편입" 버튼 클릭 → 선택된 부원 한번에 배정
3. 부원이 많을 때(100명+) 드래그보다 편리

- 같은 부원을 다른 팀에도 배정 가능 (멀티팀 소속)

##### 필터 & 검색 (일반부원 섹션)

- **필터**: 미소속만 / 전체 (토글)
- **이름 검색**: 부원 100명+ 대비, 검색으로 빠르게 찾아서 드래그
- 이미 팀에 배정된 부원도 "전체"에서 보임 (다른 팀에 추가 가능하므로)

##### 접근 권한

| 동작 | 회장/부회장 | 팀장 | 일반부원/졸업자 |
|------|-----------|------|--------------|
| 화면 열람 (조직도 보기) | ✅ | ✅ | ✅ (읽기 전용) |
| 역할 변경 (`[역할 ▾]`) | ✅ | ❌ | ❌ |
| 팀 생성 (`[팀+]`) | ✅ | ❌ | ❌ |
| 자기 팀에 부원 배정 (드래그/체크박스) | ✅ (모든 팀) | ✅ (자기 팀만) | ❌ |

##### 멀티역할/멀티팀 케이스

- 부회장이면서 팀장: 상단 부회장 영역 + 중간 팀장 탭 양쪽에 표시
- 팀장이 2개 팀: `[팀+]`로 팀 추가, 탭으로 전환, 테두리 색 다름
- 팀장이면서 다른 팀 팀원: 다른 팀장 테두리 안에도 이름 표시됨

#### 5.2 팀 스페이스 — 팀원 목록 & 팀 프로필 ✅ 구체화 완료

> 위치: **TeamSpacePage (`/club/team/:teamId`)** 상단 영역

##### 팀 헤더 (상단)

- 팀 이름, 팀장, 멤버 수 등 기본 정보
- 팀원 목록 (역할 구분 표시)
- UI 배치는 구현 시 판단

##### 팀 정보 컴포넌트 — Key-Value 커스텀 방식

> 하드코딩된 필드가 아닌, 팀장이 자유롭게 항목을 추가/삭제하는 소프트 구조

```
┌─────────────────────────────────────┐
│  팀 정보                    [✏️]    │  ← 팀장/임원만 수정 아이콘 표시
│                                     │
│  팀 소개    주식분석 위주 팀이에요    │
│  정기일정   매주 화요일 19시         │
│  연락처     카톡 오픈채팅 링크       │
│  투자 성향  가치투자 + 모멘텀        │
│                                     │
│  [+ 항목 추가]  ← 팀장/임원만 표시   │
└─────────────────────────────────────┘
```

- **Key**: 팀장이 직접 입력 (예: "팀 소개", "정기일정", "연락처" 등)
- **Value**: 자유 텍스트
- 팀장이 원하는 만큼 항목 추가/삭제/수정
- 편집 권한: 팀장 + 회장/부회장 (수정 아이콘 `[✏️]`으로 편집 모드 진입)
- 일반부원: 읽기만 가능

#### 5.3 플로팅 메시지 패널 (알림 + 채팅 + 캘린더) ✅ 구체화 완료

> 위치: **모든 페이지 오른쪽 하단 플로팅 아이콘** (메시지 모양)
> 성격: **개인용 허브** — 기존 공식 페이지(캘린더, 게시판 등)와 별개로, 개인이 빠르게 접근하는 단축 패널

##### 결정 변경

- ~~동아리 채팅 제거~~ → **플로팅 패널 안에 경량 채팅으로 부활**
- 종토방(스레드 보드) + 게시판은 그대로 유지, 이 채팅과 별개
- 기존 ClubCalendarPage, TeamSpacePage 일정 탭도 그대로 유지 (공식 페이지 = 동아리 전체용, 패널 = 개인용)

##### 패널 구조 — 6개 채널

```
┌─────────────────────────────┐
│  [✕]          메시지 패널    │
├─────────────────────────────┤
│  🔔 알림              (3)   │  ← 시스템 알림 (가입 승인, 역할 변경 등)
│  📢 공지방                   │  ← 회장/부회장만 작성, 나머지 읽기만
│  💬 동아리 채팅              │  ← 전체 단톡방 (동아리 생성 시 자동 생성)
│  👥 김강산팀 채팅            │  ← 소속 팀별 (팀 생성 시 자동 생성, 여러 팀이면 여러 개)
│  👥 박서준팀 채팅            │
│  ✉️  개인 채팅         (2)   │  ← 1:1 / 그룹 DM
│  📅 캘린더                   │  ← 전체/동아리/팀 필터 + 가까운 일정순
└─────────────────────────────┘
```

- 채널 클릭 → 해당 채팅/알림/캘린더 상세 화면으로 전환
- 새 메시지/알림 있으면 채널 옆에 뱃지 숫자 표시
- 플로팅 아이콘 자체에도 총 미읽음 뱃지

##### 채팅 기능

- **텍스트** + **이미지 업로드** + **커스텀 이모티콘**
- 이모티콘: SUPER_ADMIN이 업로드한 커스텀 이모티콘 팩 (SUPER_ADMIN 관리페이지에 이모티콘 업로드 API 추가)

##### 개인 채팅 채널 — 멤버 목록 + 채팅방 통합 구조

```
┌─────────────────────────────┐
│  ✉️ 개인 채팅          🔍 [+] │  ← 🔍 이름 검색 / [+] 그룹 채팅방 생성
├─────────────────────────────┤
│                              │
│  김서연              (2) 🔴  │  ← 안 읽은 메시지 → 상단 정렬

│                              │
│  박준영                      │
│  "ㅇㅋ"             어제      │
```

##### UI 디자인 철학

> 기존 페이지(홈, 게시판, 팀 스페이스 등)는 **맥시멈** — 한 화면에 여러 정보를 최대한 담는 한국식 UI.
> 이 플로팅 패널은 **개인적이고 사적인 기능**이므로 **간결하고 예쁜 UI** 필요.
> 패널 크기가 작으므로 정보 밀도보다 가독성·심미성 우선.

#### 5.6 게시글 에디터 (BlockNote 기반 블록 에디터) ✅ 구체화 완료

> 라이브러리: **BlockNote** (노션 클론 목적 React 블록 에디터)
> 적용 대상: ClubPostWritePage, 커뮤니티 글쓰기 등 모든 글 작성 화면

##### 에디터 = 노션 스타일

- `/` 슬래시 메뉴로 블록 추가 (노션과 동일 UX)
- 드래그로 블록 순서 변경
- 인라인 포맷팅 (볼드, 이탤릭, 밑줄, 취소선)
- 마크다운 붙여넣기 → 자동 블록 변환

##### 지원 블록 종류

| 블록 | 설명 |
|------|------|
| 텍스트 | 일반 텍스트 (인라인 서식 지원) |
| 제목 | H1 / H2 / H3 |
| 리스트 | 순서 / 비순서 / 체크리스트 |
| 이미지 | 드래그앤드롭 + 버튼 업로드 + 클립보드 붙여넣기 |
| 파일 첨부 | PDF 등 파일 업로드 |
| 인용 | 인용 블록 |
| 코드 | 코드 블록 |
| 구분선 | 수평선 |
| 표 | 테이블 |

##### 이미지 업로드 3가지 방식

1. **드래그앤드롭**: 파일을 에디터 영역에 드래그
2. **버튼 업로드**: 슬래시 메뉴 → 이미지 → 파일 선택
3. **클립보드 붙여넣기**: Ctrl+V로 캡처 이미지 직접 삽입

##### AI 마크다운 연동

```
AI 응답 (마크다운 텍스트)
  → 마크다운 파서
  → BlockNote 블록 JSON으로 변환
  → 에디터에 로드
  → 사용자가 수정 가능 후 게시
```

##### 저장 형식

- **블록 JSON**으로 저장 (기존 DecisionNote의 `blocks` 필드와 동일 구조)
- 렌더링: 블록 JSON → 화면 렌더링 (게시글 상세 페이지)
- 마크다운 export도 가능 (내보내기 시)

#### 5.9 크레딧 시스템 ✅ 구체화 완료

> 핵심: 크레딧은 **동아리 → 팀** 단위로 흐름. 개인 크레딧 없음.

##### 크레딧 흐름

```
[유입]
  구독 계약 시 번들 크레딧 지급 → 동아리 총 크레딧
  콘텐츠 판매 수익 (마켓플레이스에서 다른 동아리가 구매 시)

[분배]
  회장이 팀별로 크레딧 분배 (동아리 총 → 각 팀 예산)
  팀 예산 부족 시: 팀장 → 회장에게 추가 요청 → 회장이 추가 지급

[지출 — 팀 예산에서 차감]
  AI 글 생성 요청
  마켓플레이스 개별 글 구매

[지출 — 동아리 예산에서 차감]
  마켓플레이스 채널 프리미엄 구독

[소각]
  콘텐츠 판매 수수료 20%
```

##### 마켓플레이스 구매 규칙

| 구매 유형 | 구매 단위 | 누가 사나 | 비용 출처 | 열람 범위 |
|----------|----------|----------|----------|----------|
| 채널 프리미엄 구독 | 동아리 단위 | 회장/부회장 | 동아리 예산 | 동아리 전원 |
| 개별 글 구매 | 개인이 구매 | 아무 팀원 | 팀 예산 차감 | 동아리 전원 |

- **핵심 규칙**: 누가 사든 우리 동아리 인원은 다 볼 수 있음
- 개인 구매도 팀 예산에서 나감 (개인 지갑 없음)

##### 크레딧 관리 UI

- **회장**: ClubAdminPage 또는 ClubCreditsPage에서 팀별 크레딧 분배
- **팀장**: 팀 크레딧 잔액 + 사용 내역 조회
- **팀원**: 마이페이지에서 소속 팀 크레딧 잔액 읽기만
- **ClubCreditsPage**: 동아리 전체 크레딧 현황 + 팀별 잔액 + 거래 내역

#### 5.10 종토방 실시간 데이터 ✅ 구체화 완료

> 종토방의 시세 데이터 표시 방식

##### 메인 화면 (종목 미선택 시)

- 종목 리스트의 미니 그래프 → **일봉 캔들**로 대체 (동일 스케일)
- 현재가 + 등락률 표시

##### 종목 선택 시

- **일봉 캔들 차트**: 과거 N일 + 오늘 캔들 실시간 형성
- **현재가 + 등락률 + 거래량**
- 장중: 오늘 캔들 실시간 업데이트 (polling, 주기는 구현 시 조절)
- 위치: 스레드 목록 상단

##### 뉴스 연동 — 커뮤니티 전용

- 종토방에는 뉴스 표시 안 함
- 종목 관련 뉴스는 **커뮤니티 뉴스데스크**에서만 제공
- 이유: 커뮤니티 트래픽 유도 — 종토방이 모든 걸 해버리면 커뮤니티 존재 이유 약화

##### 스레드 실시간 갱신

- 새 스레드/답글은 WebSocket으로 실시간 push → 5.12에서 상세 구체화

#### 5.11 내보내기 관리 → 커뮤니티 스코프로 이관

> 내보내기 = 커뮤니티 팀 채널에 게시하는 것
> 내보낸 콘텐츠 관리(공개↔비공개, 가격 변경, 게시 취소)는 **커뮤니티 팀 채널 페이지**에서 처리
> 동아리 쪽에서는 ExportDialog(내보내기 요청)만 있으면 됨
> **→ 커뮤니티 기능 구체화 시 상세 정의 필요**

#### 5.12 WebSocket 실시간 통신 ✅ 구체화 완료

> 전부 WebSocket. polling 없음.

##### 적용 대상

| 기능 | WebSocket 이벤트 | 동작 |
|------|-----------------|------|
| 플로팅 채팅 (동아리/팀/개인/공지) | 새 메시지 수신 | 채팅 영역에 스르르 추가 |
| 종토방 — 새 스레드 | 다른 사용자가 스레드 작성 | 스레드 목록 상단에 스르르 추가 |
| 종토방 — 답글 | 다른 사용자가 답글 작성 | 답글 영역에 스르르 추가 |
| 스터디 PDF 댓글 | 다른 사용자가 댓글 작성 | 댓글 영역에 스르르 추가 |
| 알림 | 시스템 알림 발생 | 플로팅 아이콘 뱃지 업데이트 + 알림 목록 추가 |

##### 새 항목 등장 애니메이션

- **스르르 슬라이드**: 새 메시지/스레드/답글이 위에서 부드럽게 슬라이드로 추가
- 갑자기 툭 나타나지 않음 — 자연스러운 transition

##### 연결 방식

- 로그인 후 **자동 연결** (앱 전체에서 하나의 WebSocket 연결 유지)
- 채팅방/스레드 진입 시 해당 room에 join
- 이탈 시 room에서 leave
- 연결 끊기면 자동 재연결 (exponential backoff)

#### 5.13 드라이브 + 스터디 + PDF 뷰어 ✅ 구체화 완료

> 핵심: 드라이브 = PDF 저장소 (태그 기반, 옵시디언 구조). 폴더가 아닌 태그로 분류.

##### 드라이브 아키텍처

**플랫폼 레벨에 하나의 드라이브** → 동아리별로 할당 (격리)
- 펀드메신저 프로젝트가 하나의 드라이브이고, 각 동아리가 자기 영역을 할당받아 사용
- 다른 동아리의 드라이브는 **접근 불가** (완전 격리)
- "팀 드라이브", "마이 드라이브"는 별도 저장소가 아니라 **동아리 드라이브의 필터 뷰**

##### 태그 체계 (옵시디언 방식)

모든 PDF에 **태그가 붙어서** 여러 뷰로 볼 수 있는 구조:

```
PDF 하나에 붙는 태그들:
- 기수: 33기                    ← 기수 전환 시에도 태그 유지
- 팀: 김강산팀                   ← 팀 해체되어도 태그 유지
- 주차: 1주차 스터디
- 작성자: 정다은
- 스터디 세션: 2월 3주차 세미
```

**같은 PDF를 여러 뷰로 열람:**
- **기수별 보기** → 33기 자료 전체 / 34기 자료 전체
- **팀별 보기** → 김강산팀 자료 전체
- **주차별 보기** → 1주차 스터디에 연결된 자료 전체
- **사람별 보기** → 정다은이 올린 자료 전체
- 복합 필터 가능 (예: "33기 + 김강산팀 + 1주차")

##### 기수 전환 시 드라이브 동작

- 이전 기수 PDF는 **삭제 안 됨** — 아카이브로 보존
- 팀 해체 = 팀원 소속 관계 초기화일 뿐, **PDF에 붙은 팀 태그는 그대로 유지**
- 동아리 드라이브에서 기수 필터로 이전 기수 자료 언제든 열람 가능
- 예: 35기가 된 후에도 "33기 + 김강산팀" 필터로 당시 자료 전부 열람 가능

##### 드라이브 접근 경로

| 뷰 | 진입 위치 | 필터 | 비고 |
|----|----------|------|------|
| **동아리 드라이브** (실체) | ClubAdminPage 내 탭 | 기수 / 팀 / 주차 / 사람 | 자주 들어갈 기능 아님 + 기수 단위 관리이므로 관리페이지가 맥락상 적합 |
| **팀 드라이브** (필터 뷰) | TeamSpacePage 내 탭 | 해당 팀 자료만 | 팀 스페이스에서 자연스럽게 접근 |
| **마이 드라이브** (필터 뷰) | 마이페이지 내 섹션 | 내가 올린 자료만 + 기수 필터 | 내가 활동한 모든 기수(32기~35기 등)의 자료를 기수별 필터로 조회 |

- 동아리 드라이브는 별도 LeftNav 메뉴까지는 불필요 (빈번한 접근 아님)
- 팀/마이 드라이브는 각각의 홈 페이지에서 자연스럽게 접근

##### 드라이브 권한

- **열람 권한**: 동아리 소속이면 누구나 (졸업자/유령 포함, 이전 기수 포함)
- **업로드 권한**: 동아리 인원 전체 (자기 이름으로 업로드)
- **PDF만 업로드 가능** (다른 파일 형식 불가)

##### 스터디 = 태그(컨테이너)

- 회장/부회장이 "1주차 스터디" 같은 태그(세션) 생성
- 팀장이 스터디 진행할 때 해당 태그에 연결
- PDF는 여러 태그에 동시 연결 가능
- **참여자 별도 관리 없음** — 자료 올린 사람 = 자동으로 참여자. 참관인은 열람만.

##### PDF 뷰어 (팝업 형태)

```
┌──────────────────────────────────────────────┐
│  [PDF 뷰어]                    [📄][📄][📄] │
│                                  ↑ 같은      │
│  PDF 렌더링 영역                  스터디의    │
│  (페이지 넘기기 등)               다른 PDF들  │
│                                  아이콘 클릭  │
│                                  → PDF 전환  │
├──────────────────────────────────────────────┤
│  댓글 영역 (현재 보고 있는 PDF에 대한 댓글)    │
│  · 김강산: PER 비교 부분 근거가 약한듯         │
│  · 박서준: p.12 차트 좋다                     │
│  [댓글 입력...]                              │
└──────────────────────────────────────────────┘
```

- **팝업 형태**: 드라이브에서 PDF 클릭 시 오버레이/모달로 뷰어 열림
- **우측**: 같은 스터디의 다른 PDF 아이콘 목록 → 클릭하면 PDF 전환
- **하단**: 현재 보고 있는 PDF에 대한 댓글 스레드
- **페이지 네비게이션**: 이전/다음 페이지 버튼, 페이지 번호 표시

##### AI 글 생성 (팀장 기능)

```
팀장이 PDF 뷰어에서 "AI 문서 작성" 클릭
  → AI에 전달: 해당 PDF 내용 + 해당 PDF의 댓글들
  → AI가 기업분석 글 초안 생성
  → BlockNote 에디터에 로드 → 수정 후 게시
  → 팀 예산 크레딧 차감
```

### 7.3 기술 설계 — 확정

#### ✅ 파일 저장소

**로컬 볼륨 + 추상화 인터페이스**
- Docker 환경: `/data/uploads/` 볼륨 마운트
- `FileStorageService` 인터페이스로 추상화 → 배포 시 Oracle Object Storage 구현체로 교체만
- 디렉토리 구조:
```
/data/uploads/{orgId}/images/    — 채팅/게시글/프로필 이미지 (압축본)
/data/uploads/{orgId}/pdfs/      — 드라이브 PDF
/data/uploads/emoji/             — 커스텀 이모티콘 (전체 공유)
```

#### ✅ BlockNote 블록 JSON 스키마

- 기존 DecisionNote의 blocks (Editor.js 포맷, V1 레거시)와 **분리**
- **BlockNote 네이티브 JSON 포맷 사용**
- ClubPost 테이블: `content` 컬럼을 TEXT → JSONB로 변경
- 기존 TEXT 데이터 마이그레이션: `{"type": "text", "content": "기존 내용"}` 래핑

#### ✅ 채팅 엔티티 설계

```
ChatRoom
├── id (PK)
├── type: CLUB / TEAM / DM / GROUP
├── organizationId (FK)
├── teamId (nullable, TEAM 타입일 때만)
├── name
├── createdAt
└── 관계: 1:N → ChatMember, 1:N → ChatMessage

ChatMember
├── id (PK)
├── chatRoomId (FK)
├── userId (FK)
├── lastReadMessageId (안읽음 카운트 계산용)
├── joinedAt
└── 인덱스: (chatRoomId, userId) UNIQUE

ChatMessage
├── id (PK)
├── chatRoomId (FK)
├── senderId (FK)
├── type: TEXT / IMAGE / EMOJI / SYSTEM
├── content (텍스트 or 이미지 URL or 이모티콘 ID)
├── createdAt
└── 인덱스: (chatRoomId, createdAt)
```

**Announcement — ClubPost와 분리 (별도 엔티티)**

> 이유: 공지는 채팅 형태(시간순 쌓임) + 고정/배너 기능이 있어서 게시글과 성격이 다름

```
Announcement
├── id (PK)
├── organizationId (FK)
├── authorId (FK)
├── title
├── content (TEXT)
├── isPinned (Boolean)
├── pinOrder (Integer, 고정 공지끼리 드래그 순서)
├── isBanner (Boolean, 메인 배너 표시 여부)
├── createdAt
└── 인덱스: (organizationId, isPinned, pinOrder)

CustomEmoji
├── id (PK)
├── name
├── imageUrl
├── uploadedBy (FK, SUPER_ADMIN)
├── createdAt
```

#### ✅ WebSocket room 네이밍

기존 Discussion WebSocket 구조를 확장, room prefix로 분기:

```
/ws/chat/club/{orgId}                  — 동아리 전체 채팅
/ws/chat/team/{teamId}                 — 팀 채팅
/ws/chat/dm/{chatRoomId}               — DM / 그룹
/ws/notification/{userId}              — 개인 알림 (시스템 알림 push)
/ws/jongtobang/{orgId}/{stockCode}     — 종토방 스레드 (답글 실시간)
/ws/study/{materialId}                 — 스터디 PDF 댓글
```

**이벤트 포맷:**
```json
{
  "type": "NEW_MESSAGE" | "TYPING" | "READ" | "NEW_THREAD" | "NEW_REPLY",
  "roomId": "...",
  "payload": { ... },
  "timestamp": "ISO-8601"
}
```

#### ✅ DriveFile / DriveTag 설계 — M:N 정규화

> JSON 필드 대신 M:N으로 가는 이유: 태그별 검색/필터가 핵심 기능이라 인덱싱 필요

```
DriveFile
├── id (PK)
├── organizationId (FK)
├── uploaderId (FK)
├── fileName
├── fileUrl
├── fileSize
├── createdAt
└── M:N → DriveTag (via DriveFileTag)

DriveTag
├── id (PK)
├── organizationId (FK)
├── type: GENERATION / TEAM / WEEK / AUTHOR / STUDY_SESSION
├── value ("33기" / "김강산팀" / "1주차" / "정다은" / "2월 3주차 세미")
├── createdAt
└── 인덱스: (organizationId, type, value) UNIQUE

DriveFileTag (중간 테이블)
├── driveFileId (FK)
├── driveTagId (FK)
└── PK: (driveFileId, driveTagId)
```

#### ✅ 졸업자 권한 설정 — Organization JSON 필드 확장

> 별도 테이블 불필요 — Organization 설정의 일부

```
Organization 테이블 확장:
├── ... (기존 필드들)
├── graduatePermissions JSONB DEFAULT '{
│     "clubChat": true,
│     "calendar": true,
│     "announcements": true,
│     "dm": true
│   }'
```

- 회장/부회장이 ClubAdminPage 설정 탭에서 토글로 변경
- 기본값: 전부 허용 (true)
